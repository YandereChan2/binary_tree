# 返回值与所有权

侵入式二叉树**不拥有节点**：节点由用户创建和销毁，树对象只维护链接。几个修改器会
把一棵子树从当前位置换出，并以**独立的树对象**返回。这个返回值不是可选的“附带
信息”，而是子树的唯一树句柄；丢弃它通常意味着子树从此无法再被访问。

## 总表

| 函数 | 返回值 | 丢弃返回值的后果 |
|:-|:-|:-|
| `insert(pos, n)` | 拥有被换出原子树的树对象 | 临时树析构时 `clear()`：节点脱管但不销毁；没有其他指针时无法再访问，等同泄漏 |
| `cut(e)` | 拥有被摘下子树的树对象 | 同上 |
| `splice(to, from)` | 拥有 `to` 处原子树的树对象 | 同上 |
| `erase(e)` / `clear()` | 无 | 节点按语义脱管；`erase(e, del)` 可由 `del` 销毁 |
| 树对象析构 | 无 | 自动 `clear()`：节点脱管，不销毁 |
| `swap` / `swap_sub_tree` / `swap_node` / 旋转 | 无 | 不销毁节点 |

## 典型用法

```C++
// 正确：接住被换出的原子树
auto old = tree.insert(tree.root(), n);
old.clear(); // 先让 old 里的节点脱管，再销毁它们

// 错误：返回值被丢弃，临时树析构时会 clear()，节点被脱管
tree.insert(tree.root(), n); // 若没有其他节点指针，子树从此无法访问
```

## “销毁”的两种含义

文档里必须区分：

1. **销毁树对象**：调用树的析构函数。它只 `clear()`，让节点脱管，**不销毁节点**。
2. **销毁节点**：对节点调用析构 / `delete`，或使用 `erase(e, deleter)`。只有脱管节点
   可以这样做。

因此，`insert` / `cut` 返回的树对象即使被销毁，节点也仍然存活但脱管；不过因为返回
值被丢弃时你通常已经拿不到这些节点，实际效果是泄漏或无法再访问。正确做法是保留返回
值，并在需要销毁节点时先对返回的树 `clear()` / `erase()`，再销毁节点。

## 与非侵入式容器的区别

`Yc::binary_tree` 返回的 `binary_tree` **拥有**被换出的子树；丢弃返回值会直接销毁
节点。侵入式版本返回的树只拥有“句柄”而不拥有节点；丢弃返回值不会销毁节点，但会
丢失句柄。详见
[非侵入式树的返回值与所有权](../binary_tree_readme/ownership_and_return.md)。

## 异常安全

侵入式的结构操作都是 `noexcept`，不会因分配或元素构造抛出（本层不分配也不构造 `T`）。
`erase(e, del)` 要求 `del` 不抛出；抛出会调用 `std::terminate`。
