# 代理失效规则

本文说明侵入式二叉树的四种代理在什么情况下仍然可用。所有“失效后使用”都是行为
未定义。

## 快速规则

| 代理 | 有效条件 | 失效 / 不可用的情况 |
|:-|:-|:-|
| `edge_proxy` / `edge_const_proxy` | 它指向的槽位所在节点（或哨兵）仍存活 | 节点被销毁；`erase` / `clear` / 树析构让传入的槽位变空；节点被脱管后槽位指向自身，不能导航 |
| `node_proxy` / `node_const_proxy` | 它指向的节点仍存活 | 节点被 `erase` 的回收器销毁；节点被用户提前销毁 |
| 元素引用 / 用户数据 | 节点仍存活 | 与 `node_proxy` 相同 |

## edge_proxy

边代理绑定的是**槽位**，不是槽位里当时的节点。

- `root()` 返回的根边代理在树对象生存期内一直有效；树为空时它仍然有效，只是
  `null() == true`。
- `get_left()` / `get_right()` / `get_children()` 返回的边代理以父节点仍存活为前提；
  父节点被销毁后，这些代理指向已释放对象的成员，全部失效。
- `insert` / `splice` 会把新子树放入目标槽位，槽位本身不变；代理仍然有效，但
  `operator*` 现在访问的是新节点。
- `erase` / `clear` / `cut` 会让**传入的那个槽位**变空（`null() == true`）。被摘下的
  子树**内部**的槽位则随节点一起保留：如果节点只是脱管，槽位指向节点自身，边代理仍然
  存在但导航是未定义行为；如果回收器销毁了节点，槽位随节点一起失效。
- `swap_sub_tree` 交换两个槽位的内容；代理仍然分别指向原来的槽位，但槽位里的节点
  换了。
- `swap_node` 在相邻父子情形下会改变节点身份；调用前取得的边代理可能从此指向另一个
  节点。需要继续操作时请重新取得代理。
- 节点析构会连同它的 `left` / `right` 成员一起销毁；指向这些成员的边代理随之失效。

**注意**：节点被 `clear` / `cut` 脱管后，槽位仍然存在，但里面的链接指回节点自身。
此时 `null()` 可能返回 `false`，但**导航是未定义行为**。边代理只在节点处于纳管状态时
用于导航。

## node_proxy

节点代理绑定的是**节点地址**。本库的节点不会被树操作搬移，所以节点代理在节点存活
期间保持有效：

- `insert` / `cut` / `splice` / `swap` / `swap_sub_tree` / `swap_node` / 旋转都不会
  改变节点地址，节点代理继续指向同一个节点；
- `erase(pos)`（不带回收器）只让节点脱管，不销毁节点；节点代理仍然有效，但节点处于
  脱管状态，不能导航；
- `erase(pos, deleter)` 在回调中销毁节点；回调返回后，指向该节点的代理失效；
- `clear()` 只脱管，不销毁；节点代理仍然有效，但节点脱管，不能导航；
- 树对象析构现在会调用 `clear()`；节点代理仍然有效，但节点脱管；
- 如果用户直接销毁了一个纳管节点，这本身就是未定义行为，所有相关代理自然失效。

节点代理不关心节点当前在哪个槽位；它只关心节点地址。

## 元素引用和用户数据

`operator*` 返回的 `node_base&` 以及用户 `static_cast` 得到的 `T&` 与节点代理同寿命：
只要节点没有被销毁，引用就有效。节点被 `erase` 的回收器销毁、或被用户直接销毁时，
引用失效。

## 不使节点失效的操作

以下操作只改链接，不销毁节点：

- `swap`、`swap_sub_tree`、`swap_node`；
- `left_rotate` / `right_rotate`；
- `insert` / `cut` / `splice`（节点仍在，只是换了一棵树或一个槽位）；
- `erase(pos)`（不带回收器）、`clear`、树对象析构（节点脱管但存活）。

它们可能让 `edge_proxy` 指向不同的节点、让槽位变空，或者让节点脱管；具体见上文。
